# Internationalization

Tusk ships two locales: English (the default and the fallback) and Simplified
Chinese. Translations live in `locales/en.yml` and `locales/zh-CN.yml`,
embedded at compile time by [rust-i18n]; the language is a runtime setting
(⌘, → General → Language) that takes effect immediately, without a restart.

## How it works

- `src/main.rs` calls `rust_i18n::i18n!("locales", fallback = "en")` at the
  crate root, which generates the lookup `t!` resolves to.
- `src/i18n.rs` holds the plumbing: the `crate::tr!("key", name = x)` macro
  (a `t!` that returns an owned `String`), the `ActiveLocale` GPUI global, and
  `set_language` — which persists `Prefs.language`, switches the locale,
  rebuilds the native menu bar (`menus::refresh`), refreshes placeholders of
  inputs built once per window (`TuskApp::sync_localized_placeholders`) and
  redraws every window.
- With Language = "System" the OS locale picks the locale (`zh*` → zh-CN,
  anything else → en). First launch therefore opens in Chinese on a Chinese
  desktop.

## Rules for translated code

- **Translate where the string is built for display** — in `render`, or at the
  moment a toast/status entry is produced. Do not cache translated text in
  long-lived struct fields: it freezes in the language it was built in.
  Secondary windows (New Connection, Settings, Export…) are rebuilt per open,
  so construction-time `tr!` is fine there.
- **Translate the display, never the storage.** Some settings persist the
  English display string as their canonical value (accent color "Teal",
  "Contains", "Primary key ascending", …). Those stored values stay exactly as
  they are; pickers use `(value, label)` pairs and translate only the label.
  Same for SQL keywords (`NULL`, `IN`, `LIKE`) and DB object names.
- **rust-i18n has no plural rules.** Counts use two keys —
  `status.saving_one` / `status.saving_many` — selected by `count == 1`.
- **Never translate:** logs, serde field names, paths, generated SQL/DDL/dump
  content, raw error causes from drivers or child processes (the template
  around them is translated, the cause arrives as a `%{error}` parameter),
  brand and product names (Tusk, PostgreSQL, Claude, Omarchy…), keyboard
  glyphs, and technical samples (`HH:MM:SS`, `postgresql://…`).
- Keys are checked at compile time, so they must be literal strings. Inside
  `#[cfg(test)]` modules of files that use `tr!`, import from `super`
  explicitly — a `use super::*;` glob also pulls the generated crate-root
  macros and breaks `#[test]` expansion.

## Locale files

Both files hold the same dotted-key tree, grouped by feature:

```yaml
status:
  connecting: Connecting to %{name}…
palette:
  connection:
    connect: connection: connect to %{name}
```

- English values must stay byte-identical to the original UI text.
- `%{name}` interpolation slots must match between en and zh-CN.
- `cargo test -- i18n` fails on any key or placeholder mismatch — CI runs it.
- Missing keys fall back to English at runtime.

## Adding a language (example: Japanese)

1. Copy `locales/en.yml` to `locales/ja.yml` and translate the values. Keep
   the key tree and every `%{…}` slot identical.
2. `src/i18n.rs`: add `pub const LANG_JA: &str = "ja";`, extend `LANGUAGES`,
   and map the OS locale in `resolve` (`ja*` → `LANG_JA`).
3. `src/settings.rs`, General page → Language dropdown: add a
   `(SharedString::from(crate::i18n::LANG_JA), "日本語".into())` entry
   (values are the locale ids; labels are the language's own name).
4. `cargo test -- i18n`, then run the app with `LANG=ja_JP.UTF-8` and switch
   to the new language live.
5. Check layout: longer strings can truncate in the sidebar, the status bar
   and menu items; IME composition in the SQL editor and filter inputs.

## zh-CN glossary

| English | 简体中文 |
| --- | --- |
| Connection | 连接 |
| Database / Schema | 数据库 / 模式 |
| Table / View / Structure | 表 / 视图 / 结构 |
| Query / Editor | 查询 / 编辑器 |
| Filter / Sort | 筛选 / 排序 |
| Backup / Restore | 备份 / 还原 |
| Export / Import | 导出 / 导入 |
| Changes: Save / Discard | 提交更改 / 放弃更改 |
| Tab / Sidebar / Console | 标签页 / 侧边栏 / 控制台 |
| History | 历史记录 |
| Agent | 智能体 |
| Settings / Appearance / Theme | 设置 / 外观 / 主题 |

Conventions: desktop-app register (short, no 您/你), full-width punctuation
(：、（）…), ellipsis `…`, a space between CJK and Latin/digits, product and
engine names kept in English (Tusk, SQL, PostgreSQL, pg_dump…).
